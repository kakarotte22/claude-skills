AI 产品面试三讲

边界 · 技术栈 · 客户画像
—— 三道高频题，一条方法论

手稿一册五节建议精读 25 分钟荧光笔已划好重点

这份手稿整理了 AI 产品岗面试中出现频率最高的三道题：产品的边界在哪、技术栈要懂到什么程度、目标客户是谁。三道题看似独立，背后其实是同一条判断链——边界回答「该不该做」，技术栈回答「怎么做、花多少钱」，客户画像回答「谁为此付钱」。每讲按同一结构展开：核心论点、框架、你的牌、可背诵话术、雷区。

三道题，一条线

把它们答成一套体系，而不是三个孤立的点

这三道题不是三个孤立考点，而是同一条逻辑链上的三环。面试官在每道题里各自埋了一层考察意图——边界考体系化判断力，技术栈考技术权衡感，客户画像考商业化思维——但串起来答，展示的是最稀缺的体系化思维：一个完整的商业判断刚好闭环。

容错率低的边界 → 决定技术栈里要配护栏与评估体系 → 决定交付成本 → 决定谁能付得起钱。

面试时主动把三题串起来讲：在技术栈里提到容错率，在客户画像里提到边界，在边界里提到成本——每道题都从上一道题的结论出发，这是普通候选人和体系化候选人之间的分水岭。

壹 第一讲 · 产品的边界
第一讲 LECTURE 01 · 考察：体系化判断力

AI 产品的边界在哪

筛选题——考的不是结论，是方法论

面试官意图：想看的不是「AI 有幻觉、会出错」这类人人都会说的结论，而是你有没有一套「什么交给 AI、什么留给人和确定性系统」的判断方法论。回答的关键是给出决策框架 + 具体例子。

核心论点

AI 产品的边界不在「AI 能不能做」，而在「做错了怎么办」——由错误代价、可验证性、责任归属三个变量共同决定。

一能力边界：概率系统 vs 确定性系统

  • LLM 本质是概率生成，输出「通常对」但不保证对。凡是要求 100% 确定的环节（资金划扣、权限授予、数据删除），不能交给 AI，必须用规则和代码兜底。
  • 推理是「拟合」而非「计算」：复杂多步算术、严格逻辑链、长程规划仍然不可靠。
  • 反过来看，模糊、非结构化、没有标准答案的任务（总结、抽取、改写、多轮对话）恰恰是 AI 的主场——传统代码做不了，AI 做到 80 分就是巨大增量。

产品含义：AI 适合做「从 0 到 70 分」的跃迁，不适合做「从 99 到 100 分」的冲刺。

二场景边界：容错率决定产品形态

产品设计的功夫全在这个矩阵里：容错率越低，人机协作的接缝设计越重要——AI 负责压缩工作量，人负责把关最后一公里。

三责任边界：AI 永远不能是责任主体

  • AI 不能承担责任，所以最终决策权和署名权必须落在人或机构。在金融、医疗、法律等强监管行业，这是硬约束，不是产品设计偏好。
  • 对应的设计模式：AI 输出必须可解释、可追溯、可驳回；高风险动作强制 human-in-the-loop；监管场景下（生成式 AI 管理办法等）还有内容合规、数据来源等要求。

四商业边界：AI 是产品还是功能

  • 很多场景里 AI 只是功能增强（更好的搜索、更快的客服），不构成独立产品——这类场景用 API 就够了，不值得从零造。
  • 只有当 AI 带来交互范式的改变（自然语言成为主要入口、任务级交付替代工具操作）时，才值得做 AI 原生产品。
  • 还有一条隐性边界：单位任务成本——token 成本高于被替代的人力成本时，商业模式不成立。
你的牌 · 风控背景

风控恰好是把「模型边界」工程化得最好的领域——模型只输出概率分，而截断规则、人工审核队列、额度策略、回捞机制，全是在给模型边界做补丁。这段经验可以直接迁移：判断一个 AI 功能该不该做的第一反应，就是「它错了之后，有没有兜底路径，兜底成本是多少」。

面试话术 · 可背诵

我在风控里天天处理边界问题：模型给分数，但拒绝 / 放行的最终动作永远由策略和人来定。这套思路迁移到 AI 产品是一样的——AI 负责把不确定性压缩成结构化的建议，确定性系统和人负责执行。所以我判断一个 AI 功能该不该做，第一个问题就是：它错了之后，我们有没有兜底路径，兜底成本是多少。

常见失分点

雷三个雷区

  1. 别只说「AI 有局限」——不给出判断框架，等于没回答。
  2. 别把边界说成静态——要补一句「边界在移动」（去年做不到的 agent 任务今年能做了），说明你追踪技术演进，边界判断需要持续重估。
  3. 别显得 AI 悲观——框架的落点是「正因为有边界，才需要产品设计」：边界是产品经理的价值所在，不是 AI 的失败。
贰 第二讲 · 技术栈
第二讲 LECTURE 02 · 考察：技术权衡感

AI 技术栈要懂到什么程度

不是会实现，而是能权衡

面试官意图：「了解 AI 技术栈」的潜台词是——你能不能参与技术方案讨论、听懂工程团队的话、对技术选型做出有依据的判断。回答的姿态：分层地图 + 每层的关键决策点，而不是背名词。

核心论点

技术栈不是名词清单，而是一组决策：每一层都有「用不用、用哪个、什么时候换」的权衡。分层结构和决策框架是稳定的，具体组件每半年一变——掌握前者。

一一张四层地图

二中间层是主战场：一条决策链走天下

最高频的考点就是「什么时候用什么技术」，一条决策链覆盖大半提问：

Prompt零成本 · 快迭代 → RAG知识外挂 → 微调行为固化

成本与侵入性递增——永远从左往右试。

甲Prompt 工程

解决 60–70% 的问题，零成本、可快速迭代。few-shot、思维链（CoT）、结构化输出都是这里的工具。

乙RAG

模型知识过时、私有领域知识缺失时用。链路：切分 → embedding → 检索 → 重排 → 生成。PM 要盯的不是向量库选型，而是知识库质量、切分策略、检索命中率——这些决定产品效果上限。

丙微调（SFT / LoRA）

只有需要固化「风格 / 格式 / 领域行为」、且有上千条高质量标注数据时才值得做。微调不解决知识更新——那是 RAG 的事。把这个区分说清楚，本身就是加分项。

丁Agent

核心是工具调用 + 规划 + 循环执行。PM 的判断点是任务的可验证性与容错率——直接衔接第一讲的边界框架，面试时主动串起来会非常出彩。

三应用层两个必答题

生成式产品怎么评估效果？

没有标准答案时：离线建 eval 集（golden set + LLM-as-judge），线上看人工采纳率 / 修改率 / 留存。指标设计比模型选型更重要。

怎么控制坏输出？

护栏分层：输入侧过滤 → 模型约束（结构化输出、拒答策略）→ 输出侧校验 → 高风险动作人工确认。

你的牌 · 风控背景

做过完整的「训练 → 评估 → 部署 → 监控」闭环——这套功底正是 AI 应用工程（LLMOps）最稀缺的。风控的离线评估（KS / AUC）对应 LLM 的 evals 体系，线上监控与回捞对应 guardrails 与反馈闭环；大数据背景（MaxCompute / 数仓）对应知识库与语料建设——RAG 效果的决定因素。数据侧和评估侧是主场，模型 API 的调用细节可以很快补上。

面试话术 · 可背诵

我对技术栈的理解是从模型全生命周期来的：风控模型上线前有离线评估（KS / AUC），上线后有监控和回捞——这套方法论对应到 LLM 就是 evals 体系、guardrails 和线上反馈闭环。很多人只关注模型层，而我认为决定 AI 产品成败的，恰恰是评估和数据闭环这层工程配套。另外我的大数据背景对应的是知识库和语料建设，这是 RAG 效果的决定因素——数据侧和评估侧是我的主场，模型 API 的调用细节我可以很快补上。

常见失分点

雷三个雷区

  1. 别背模型参数和架构（transformer 几层、attention 怎么算）——说了反而显得定位不清，除非面的是技术型 AI PM。
  2. 别漏掉「成本」这条线——面试官问技术栈时，暗中在考察商业意识；主动算 token 成本账是加分项。
  3. 别把技术栈说成静态清单——收尾补一句：技术栈每半年一变（比如今年 MCP 标准化了工具调用），但分层结构和决策框架是稳定的，我掌握的是后者。这句话本身就是认知深度的证明。
叁 第三讲 · 客户画像
第三讲 LECTURE 03 · 考察：商业化思维

强应用大模型的目标客户画像

从「技术能做什么」到「谁愿意付钱、为什么付」

面试官意图：考商业化思维。大部分人会答成行业罗列（金融、医疗、教育……），那等于没答——好的回答给出特征维度，行业只是特征的投影。

核心论点

目标客户不由行业定义，而由四个特征定义：认知劳动密集、数据基础好、ROI 算得清、容错率匹配。行业清单只是筛选结果。

一四个特征维度

  1. 认知劳动密集——组织里存在大量重复性知识工作（客服问答、文档审阅、报告撰写、代码、营销素材）。大模型能规模化替代的只有认知劳动，替代体力劳动是机器人公司的事。量化抓手：知识型岗位的人力成本占比。
  2. 数据基础好——语料已电子化、有沉淀、质量可控。RAG 的效果上限由知识库质量决定；数字化落后的客户需要先补信息化课——他们是系统集成商的客户，不是大模型应用的客户。
  3. ROI 算得清——有量化基线可对照：客服有人均接线量、营销有转化率、研发有代码采纳率。算不清账的场景只能做 POC，做不成生意。
  4. 容错率匹配——容错高就全自动交付，容错低就 AI 辅助 + 人把关（衔接第一讲的边界框架）。容错率同时决定产品形态和交付成本，直接影响客单价能不能覆盖。

二行业渗透梯度：谁先买单

三客户分层 × 商业模式

一个值得主动讲的趋势判断：决策者正在从 CTO / 信息化部门下移到业务部门——2023 年是技术尝鲜者为「战略故事」买单，2024–2025 转入价值验证期，业务负责人只认「省了几个人、涨了多少转化」。谁验收，决定了你的产品文档写给谁看。

四反向画像：谁不是客户

  • 数字化程度低的组织——先解决信息化，再谈智能化；他们是系统集成商的客户，不是大模型的客户。
  • 痛点在流程和组织、而非认知劳动的客户——AI 解决不了管理问题。
  • 想要「一个 AI 什么都干」的客户——POC 幻觉客户，验收永远过不了，要靠场景聚焦的销售纪律主动筛掉。
  • 单位任务 token 成本高于被替代人力成本的场景——账算不过来，模型降价前不碰。

敢定义「不服务谁」，比罗列「服务谁」更能证明你懂 to B。

你的牌 · 风控背景

金融就是画像里第一梯队最典型的客户：风控本身就是数据生意；智能客服、审贷材料核验、研报生成全是认知劳动密集场景。金融监管要求可解释、可追溯，反而催生了「模型输出 + 策略兜底 + 人工复核」的标准产品形态——我在风控里做的，正是这套架构的落地。

面试话术 · 可背诵

我所在的金融行业就是画像里最典型的客户：风控本身就是数据生意，智能客服、审贷材料核验、研报生成全是认知劳动密集场景；而且金融监管要求可解释、可追溯，反而催生了「模型输出 + 策略兜底 + 人工复核」的标准产品形态——我在风控里做的正是这套架构的落地。所以我看 AI 应用客户，第一反应是去拆它的认知劳动在哪、数据在哪、错误代价多大，这三个问题答完，这个客户值不值得做基本就清楚了。

常见失分点

雷三个雷区

  1. 别答成行业清单——没有特征维度，面试官会认为你只是背了报告。
  2. 别只说谁买单、不说谁不买单——客户画像的价值一半在排除。
  3. 别说成静态的——画像随「单位智能成本」曲线移动：推理成本每降一档，原来算不过账的场景（营销素材、客服全量替代）就会滚进目标客户范围，画像需要定期重估。

万能答题骨架
  1. 一句话观点——先给结论，不让面试官等；

「AI 负责把不确定性压缩成结构化的建议，
